Quickstart

شروع در ۵ دقیقه

توکن را از @botfather در بله بگیر. پارامتر bot خودکار تزریق می‌شود — لازم نیست دستی پاس بدهی.

echo_bot.py
import asyncio
from badking import Bot, Dispatcher, F

bot = Bot("123456789:TOKEN_FROM_BOTFATHER")
dp = Dispatcher()

@dp.message(F.text == "/start")
async def start(message, bot):
    await bot.send_message(message.chat.id, "⁦خوش آمدی!⁩ 🚀")

@dp.message(F.text)
async def echo(message, bot):
    await bot.send_message(message.chat.id, f"⁦شما گفتید:⁩ {message.text}")

asyncio.run(bot.polling(dp))

Self-bot / Internal API

اکانت شخصی، نه ربات

این همان چیزی است که بیشتر مردم دنبالش هستند و aiobale فقط آن را دارد. در BADKING کنار ربات رسمی هست، نه به‌جای آن.

این لایه غیررسمی است. با شماره تلفن لاگین می‌کند، نه توکن @botfather. ممکن است بشکند و ممکن است اکانتت مسدود شود. با شماره جداگانه کار کن.
selfbot.py
from badking import SelfBot

async with SelfBot(session="me.session") as bot:
    print(await bot.get_me())

    # ⁦ارسال از اکانت شخصی⁩
    await bot.send_message("@my_channel", "⁦سلام از BADKING⁩")

    # ⁦تاریخچه کامل⁩ — ⁦نه فقط ۲۴ ساعت⁩
    async for msg in bot.iter_messages("@my_channel", limit=500):
        print(msg.date, msg.text)

    # ⁦واکنش، حذف، فوروارد، تایپ⁩
    await bot.react("@my_channel", 12345, "❤")
    await bot.delete_messages("@my_channel", [12345])
    await bot.send_typing("@my_channel")

۵۸ RPC آماده

پیام، واکنش، گروه، کانال، مخاطبین، وضعیت آنلاین، فایل، کیف پول، ربات، جستجو، استیکر، تنظیمات. هر کدام با اسکیما و نام فیلد.

هر RPC دیگری هم

اگر متدی در لیست نیست، مستقیم صدایش بزن: bot.call("messaging.LoadHistory", ...). نیازی به fork نیست.

اگر بله پروتکل را عوض کرد

پروتکل داخلی بله .proto رسمی ندارد — هیچ‌کس آن را از بله نگرفته. در BADKING همه شماره فیلدها در یک جدول JSON است، نه پراکنده در کد. اگر بله چیزی را جابه‌جا کرد، BADKING_RPC_SCHEMA را عوض می‌کنی و بدون آپدیت کتابخانه وصل می‌شوی.

# ⁦فقط کیف پول⁩

# ⁦لاگین و ذخیره نشست⁩
badking login --phone 09123456789 --session me.session

۱ ویزارد چندمرحله‌ای

پرسش‌وپاسخ خطی بدون دست‌وپنجه نرم کردن با FSM:

conversation.py
from badking import Bot, Dispatcher, F, ConversationManager

bot = Bot("TOKEN")
dp = Dispatcher()
convos = ConversationManager()
dp.register_middleware(convos)

@dp.message(F.text == "/register")
async def register(message, bot):
    async with convos.conversation(bot, message.chat.id) as conv:
        await conv.send("⁦اسم کاملت چیه؟⁩")
        name = await conv.get_response(timeout=60)

        await conv.send("⁦شماره تماس؟⁩")
        phone = await conv.get_response(timeout=60)

        await conv.send(f"⁦ثبت شد⁩ ✅\n⁦نام:⁩ {name.text}\n⁦تلفن:⁩ {phone.text}")

اگر کاربر جواب ندهد ConversationTimeout می‌گیری. اگر چت دیگری پیام بدهد، مزاحم مکالمه نمی‌شود.

۲ منوی چندصفحه‌ای

pagination.py
from badking import KeyboardPaginator, F

products = ["⁦کتاب پایتون⁩", "⁦هدفون⁩", "⁦ماوس⁩", "⁦کیبورد⁩", "⁦مانیتور⁩"]
paginator = KeyboardPaginator(products, per_page=3, prefix="shop")

@dp.message(F.text == "/shop")
async def shop(message, bot):
    await bot.send_message(
        message.chat.id, "⁦محصولی انتخاب کن:⁩",
        reply_markup=paginator.markup(page=0).model_dump(exclude_none=True),
    )

@dp.callback_query(F.data.startswith("shop:"))
async def on_shop(cq, bot):
    parsed = paginator.parse(cq.data)
    if not parsed:
        return
    kind, value = parsed
    if kind == "page":
        await bot.edit_message_text(
            cq.message.chat.id, cq.message.message_id, "⁦محصولی انتخاب کن:⁩",
            reply_markup=paginator.markup(page=value).model_dump(exclude_none=True),
        )
    elif kind == "item":
        await bot.answer_callback_query(cq.id, f"⁦انتخاب شد:⁩ {products[value]}")

۳ FSM پایدار با SQLite

fsm_order.py
from badking import Bot, Dispatcher, F, State, StatesGroup, SQLiteStorage

class Order(StatesGroup):
    item = State()
    address = State()

dp = Dispatcher(storage=SQLiteStorage("orders.db"))
bot = Bot("TOKEN")

@dp.message(F.text == "/order")
async def start_order(message, state):
    await state.set_state(Order.item)
    await bot.send_message(message.chat.id, "⁦چه چیزی می‌خواهی؟⁩")

@dp.message(Order.item)
async def get_item(message, state):
    await state.update_data(item=message.text)
    await state.set_state(Order.address)
    await bot.send_message(message.chat.id, "⁦آدرس تحویل؟⁩")

@dp.message(Order.address)
async def get_address(message, state):
    data = await state.get_data()
    await state.clear()
    await bot.send_message(
        message.chat.id,
        f"⁦سفارش ثبت شد⁩ ✅\n⁦کالا:⁩ {data['item']}\n⁦آدرس:⁩ {message.text}",
    )

ربات را ری‌استارت کن — state سر جایش است.

مرز صادقانه

این‌ها را باید بدانی، نه اینکه بعداً کشف کنی.

هر کاری API رسمی بله ندهد، با توکن رسمی از هیچ کتابخانه‌ای برنمی‌آید. نه BADKING، نه aiobale، نه هیچ‌کس دیگر. این محدودیت بله است، نه کتابخانه.

تاریخچه پیام‌ها

iter_messages ما آپدیت‌های موجود را می‌پیماید. تاریخچه کامل و قدیمی‌تر از ۲۴ ساعت با توکن رسمی ممکن نیست — برای آن لایه hybrid لازم است.

ریسک self-bot

لایه hybrid پیش‌فرض خاموش است و بدون ack_risk=True فعال نمی‌شود. دلیلش: Internal API غیررسمی است، می‌شکند، و می‌تواند اکانت شخصی‌ات را ببندد.

اعداد تأییدنشده

اعدادی مثل «۴۰۹۶ کاراکتر» یا «حذف تا ۴۸ ساعت» در مستندات رسمی بله نیامده‌اند. در BADKING پیش‌فرض قابل‌تنظیم‌اند و از retry_after واقعی سرور یاد می‌گیرند.

Self-bot کامل — نه چارچوب

۵۸ RPC با اسکیما پیاده‌سازی شده: پیام، واکنش، گروه، کانال، مخاطبین، وضعیت آنلاین، فایل، کیف پول، ربات، جستجو، استیکر، تنظیمات. ورود با شماره + کد SMS کار می‌کند، تاریخچه کامل خوانده می‌شود، و از اکانت شخصی پیام می‌رود.

شماره فیلدها قابل override

پروتکل داخلی بله .proto رسمی ندارد. در BADKING همه شماره فیلدها در یک جدول JSON است، نه پراکنده در کد. اگر بله پروتکل را عوض کرد، BADKING_RPC_SCHEMA را عوض می‌کنی و بدون آپدیت کتابخانه وصل می‌شوی. این تفاوت اصلی با هر پیاده‌سازی دیگری است.
